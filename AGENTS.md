# Project Operating Guide

- This repository is a team project.
- Understand the repository before making architectural decisions.
- Preserve existing work.
- Follow workspace skills when relevant.
- Follow workspace rules.
- Verify commands and behavior instead of guessing.
- Do not claim something works without verification.
- Do not expose secrets.
- Prefer minimal, maintainable changes.
- Ask for clarification when requirements are genuinely ambiguous.
- For large changes, first explain the implementation plan and impacted files.
- After changes, report what changed and how it was verified.
